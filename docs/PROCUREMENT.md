# 采购全流程与经验闭环

入口：`/desk/buying/procurement-workspace`。原采购工作台、原生业务单据及普通问答继续使用；Supply Case / Supply Decision仍负责供应异常及处置决策。

## 操作流程

1. 在原工作台登记需求，或从已有采购类型Material Request开始。同一需求重复操作复用原流程。
2. 逐物料核对库存、预留、冻结/待检及按时在途，并记录人工核对依据。现存量不直接当作可用量，不把历史数据当实时库存。
3. 通过“准备下游草稿”衔接需求→询价、报价→采购单、采购单→收货、收货→采购发票、发票→付款。草稿需要在原生表单核对保存；正式提交、审批、外发消息和付款由有权限的人员操作。
4. “同步后续单据”按原生行引用关联；也可手动关联已引用当前上游的单据。支持拆单、合并采购、分批收货、合并开票和退货后的状态重算；无上游引用的单据拒绝关联。
5. 比价逐物料列出数量、单价、单位、币种和有效期。税费、运费、质量和交期仍需核实，不自动选供应商。财务页列出发票及订单/收货引用和未付余额，不自动核销差异或连接银行。
6. 全部需求已订购、收货数量覆盖、质量问题处理、关联订单已开票且发票结清后，由负责人结案复盘。成本须同规格、数量、币种、税费和交期口径；无基准保持“暂无法核算”，跨环节不重复累计收益。业务单据版本变化会使原复盘退出完成状态；后续普通库存变动不会改写已冻结的实际结果。

## 经验与规则

- 导入已关联的Supply Case供应通知、Supply Decision判断依据和Operations Approval审批理由。默认待核实，不伪造缺失的历史快照；核实后可作为历史参考，缺少当时快照时不参与自动学习。
- 记录场景、依据、适用条件、建议及例外，冻结判断时点的快照和来源版本。负责人核实出处及实际成效，区分未知、有效和反例；审批通过不能当作成功结果。
- 从至少5笔不同业务案例的结构化已核实经验归纳候选，按时间分为归纳集和独立留出集。同一订单链重复流程不重复计数；合成、未知、矛盾标签及旧快照缺失的记录排除。
- 本版采用可解释的结构化经验归纳，不训练模型权重、不执行文本指令。界面支持延期天数、有效报价数量、供应商、物料类别和质检拒收条件；API支持白名单组合条件。
- 至少2笔独立留出样本且无反例后，仍须负责人审核并设置一年内有效期；候选不自动启用。已观测到条件重叠但建议不同的规则须先处理冲突。同系列只生效一个版本，支持停用及重新审核旧版。新反例、撤权或依据失效时退出建议。
- 回放为观察性验证，不是因果证明或节省证明；启用后仍需收集反例。

## 问答隔离、权限与开关

只有流程内“与采购Agent讨论”附带流程标识。原主页、模块、Supply Case及采购订单会话不增加知识调用，也不修改工具白名单。历史参考由程序附加，不作为模型指令；来源重新检查当前账号权限。

自动附加使用1秒协作预算及MariaDB单条查询0.3秒上限，复用同轮经验集合，失败回滚至保存点后降级。预算在查询之间检查，不承诺整个请求严格在1秒内。显式点击查询的工作台仍按有界数据量检索。

管理员可在原生Procurement Settings表单配置：enabled关闭流程及知识扩展；knowledge_enabled只关闭知识参考；mandatory_approval要求所有正式采购单有与当前内容一致的协同批准。强制审批是独立企业策略，关闭流程或知识不会使已启用的审批策略失效；其初始关闭，重复安装不覆盖已设配置。

采购维护沿用Purchase User/Manager、Supply Planner/Approver及System Manager。结果核实和规则发布限Purchase Manager、Supply Approver、System Manager。新对象禁止通用REST直接写入；通用列表不返回敏感信息。单条读取重新校验公司、来源、库存及字段权限；来源存在不可读的高权限字段时，保守拒绝整份快照。

已有SUKE专用演示编码或公司含“演示”时自动隔离；普通合成树脂、合成橡胶等真实材料名称不作演示判据。API允许主动标记演示，不能取消来源已有标记。

## 本地部署与验证

全量构建仍使用根目录Dockerfile；迁移会增量安装对象和标准Page。现有本机镜像可增量部署，不覆盖原compose或.env：

```powershell
docker build -f deploy/Dockerfile.procurement-local -t caigou-copilot:procurement-local .
docker compose -f compose.yaml -f deploy/compose.procurement.yaml up -d --no-deps backend frontend worker scheduler websocket
docker exec caigou-copilot-backend-1 bench --site focus.local migrate
docker exec caigou-copilot-backend-1 bench --site focus.local clear-cache
```

数据库验收只在独立的 `caigou-procurement-*` 容器和 `procurement-*` 合成站点运行，需先在该站点安装与初始化合成演示数据。显式运行 `python -B tools/verify_procurement.py --container caigou-procurement-test --site procurement-test.local --url http://127.0.0.1:8095`。禁止对现有业务站点运行写验收；部署迁移与验收分别由操作者确认。

验收创建需求、询价、报价、审批、分批收货、合并开票和事务内台账付款，结束全部回滚并核对业务单数；不连接银行。规则样本用隔离夹具，审核和版本状态走真数据库，结束同样回滚。自动检查不请求真实模型、不读取密钥。

当前规模上限：每流程200张关联单、每公司单次评估500条已核实经验、最多5条适用规则及5条经验。流程列表显示最近100条；本版未接历史文件OCR、向量检索、跨企业共享或自动执行采购决策。
